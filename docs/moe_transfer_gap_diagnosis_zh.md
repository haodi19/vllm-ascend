# 搬运准备与回调间隔定位

对照基线是原回调版。MTE 路径后来加入的 CPU 重排、Storage 视图和缓存属于兼容措施，
减少这些措施的成本不能直接证明相对回调版有收益。目前不能把它们称为阻塞根因修复。

需要同时解决 `load_prepare` 增长和两个 `host_callback` 之间的间隔增长。
MEMCPY 之间的空隙包含这些阶段，但它们不能简单全部相加：存在多流重叠和其他计算。

## 使用已有采集定位

在仓库根目录运行以下只读命令，不启动模型、不重新解析 CANN 原始数据、不写结果文件：

```bash
python -B script/diagnose_moe_transfer_gaps.py bench_results_tmp/moe_debug_04/profile
```

脚本流式读取完整时间线，分别报告预取、按需的 `load_prepare` 和 `copy_submit`，
以及同层预取到按需、相邻层按需到预取的回调间隔。时间单位是微秒。
这些阶段计时含采集开销，性能对照仍以实验汇总中的无 profiler 窗口为准。

仅在设备时间线上存在唯一时间候选时，进一步拆分 MTE 回调间隔：

- `completion_to_wait_exit_us`：Python 回调结束到设备等待算子退出，包含原生工作线程
  发布完成、内存可见性及等待算子退出，不能直接解释为纯同步时间。
- `after_wait_to_publish_us`：等待算子退出到下一发布算子开始，需要结合映射写回、
  流间事件、路由回传及主流计算判断。
- `publish_us`：下一发布算子的执行时间。
- `publish_exit_to_callback_us`：发布结束到下一 Python 回调开始，涉及请求发现、
  工作线程调度、GIL 和 Python 入口，不能直接解释为纯 GIL 时间。

时间候选不等于关联 ID 证明的因果关系。多候选、区间重叠或设备命名不匹配时不强行拆分。
原回调版没有 MTE 发布和等待算子，因此只提供回调间隔基线及间隔内设备任务。
输出还列出最长间隔中的设备任务，辅助在 MindStudio 按时间戳核对。

本脚本用于确定修改位置，没有改变搬运路径，也没有宣称两个长时延问题已经修复。

## 等待结束点不在间隔内时

`moe_debug_04` 的 MTE 时间线能找到发布算子，但选定回调间隔内没有等待算子的结束点。
这不表示等待耗时为零，也不能据此判定是 CPU 线程或设备等待导致退化。
脚本现在独立报告 `before_publish_us`、`publish_duration_us`、`after_publish_us`，
三者在同一组有效样本上相加等于回调间隔；不再因等待匹配失败而丢弃发布边界。

`NEIGHBOR` 输出附近交接算子的起止时间，零点为前一个回调结束时刻。
负值表示在该时刻之前，不代表负耗时；这些仅是邻近事件，不能当作已确认的依赖。
`NON_WAIT` 单独展示间隔内非等待任务，防止其他空闲流的长等待覆盖全部输出位置。
`PREPARATION` 将准备与量化适配子项按回调次数归一化，避免混淆每专家和每回调计时。

## 本次结果与设备并行隔离实验

`moe_debug_04` 中每回调准备耗时，预取为回调版 37.344 μs、MTE 版 106.468 μs；
按需为 138.572 μs、512.859 μs。MTE 的量化适配分别占 54.598 μs、299.633 μs。
这是新增兼容路径的实测成本，含细项打点开销，且两组载入专家数量略有差异。
不能将减少这部分额外成本描述为相对原回调版的权重搬运优化。

预取到按需的间隔内，发布前为 347.155 μs，发布算子约 1.837 μs，发布后为
114.878 μs。这是导出坐标中的分段，不是已经校准的跨 CPU/NPU 唤醒计时。
邻近等待算子结束点落在 CPU 回调结束前约 87～95 μs；若关联正确，这与
“回调返回后才发布完成”的代码协议矛盾。必须核查时钟对齐及事件关联，不能
据此声称 CPU 轮询耗时 115 μs，更不能通过随意平移时间线来制造正值。

间隔中也能看到主流模型计算。当前 MTE 路径在预取发布后立即提交常驻 AIV 等待，
而原回调版不占用这个 AIV。它是否影响其他流计算的资源调度，目前是待验证假设。

```bash
python -B script/probe_mte_compute_overlap.py --npu 4
```

脚本使用已有 MTE 库，不编译、不加载模型、不写 profile；分别在独立子进程测试
原回调、只发布不启动等待、发布并启动等待三组。CPU 回调故意休眠 100 ms，释放 GIL；
在回调已经开始后，重放另一张独立计算图，检查其是否在回调返回之前完成。
每组运行三轮，子进程超时 90 秒即停止后续测试。

`OVERLAP_CONFIRMED` 是实际观察到并行；`NO_OVERLAP_OBSERVED` 不是死锁或资源冲突的
自动判定。需要结合 `submit_ms`、`compute_wait_ms` 及另外两组作判断。
这是对指定设备、算子和独立图调度的隔离实验，不是实际模型图的根因证明或性能验收。
本实验不改变模型的搬运、映射、等待顺序，不取消推理中的完成检查。
