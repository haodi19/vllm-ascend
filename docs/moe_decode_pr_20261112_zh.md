# Ascend 950PR 单卡 MoE 卸载四组实验记录：5 / 128 token

实验于2026年11月12日晚运行，本文合并同一轮token5、token128的完整性能结果与11月13日对已有trace的离线复核。
后续间隔统计没有重跑模型。本文只记录本轮已取得的数据，不沿用DT机器的HBM占用、peak activation、KV cache或专家ID明细。

## 1. 配置与测试方法

| 配置名称 | 脚本组名 | CPU–NPU交接 | LRC实现 | moe_offload_debug | worker策略 |
| --- | --- | --- | --- | --- | --- |
| 早期回调 | `callback_legacy` | `_launch_host_func` | Python | true | 不适用 |
| 当前回调 | `callback` | `_launch_host_func` | C++ | false | 不适用 |
| MTE默认 | `mte_default` | 共享内存标志＋轮询 | C++ | false | `all/locked/yield` |
| MTE组合 | `mte_combined` | 共享内存标志＋轮询 | C++ | false | `allocated/atomic/yield` |

早期回调是在当前代码上恢复早期配置，包含LRC实现与debug开关两项差异，不是历史提交的复测。
组合策略仅扫描已分配的同步任务槽，并用原子预检查减少空闲加锁；保留yield，不绑核、不启用worker内部计时。
四组都使用普通加载流；两组MTE在消费者处严格等待预取完成。权重准备与拷贝提交仍由Python/Torch完成，未启用融合规划、ACL搬运或CPU重排。

| 项目 | 本轮条件 |
| --- | --- |
| 硬件与模型 | 新PR服务器，单卡DeepSeek-V4-Flash；Prefill与Decode在同一服务中执行 |
| 执行顺序 | 每个输出长度分别依次启动早期回调→当前回调→MTE默认→MTE组合，独立服务 |
| 输入 | 每请求5个输入token |
| 短输出 | max_tokens=5，ignore_eos=false；实测5个输出token |
| 长输出 | max_tokens=128，ignore_eos=true；实测128个输出token |
| 预热与测量 | 每组预热5次，20次无profiler请求，随后单独采集1次profile请求 |
| TPOT | 流式请求的首个非空文本块至最后文本块时长 / (completion_tokens−1) |
| Host间隔 | 同一进程内前一个host_callback结束到后一个开始；区分本层预取→本层按需及按需→下一层预取 |
| 设备空泡 | 按thread_name选Stream 56，合并MEMCPY、Transpose及其他设备任务占用，保留10≤gap<5000μs |
| 窗口 | full_capture包含Prefill；callback_window是首个卸载回调开始到最后回调结束的连续窗口 |
| 分项计时 | 含profiler、MSTX与回调计时开销，不能作为无采集整体时延的可加分解 |

摘要中的“大间隔阈值100μs”属于旧逐MEMCPY统计；本文目标加载流空泡统一使用10～5000μs。
本轮摘要没有附完整服务启动参数快照，因此不以其他实验的MTP、组图或内存参数代填。

## 8. 连续空载现象与统计含义

token5每组均有11次空载预取、13次空载按需，5段多回调空泡中的完整回调全部为空载；token128每组有194次空载预取、31次空载按需。
组合版token5的2571.250μs加载流空泡内含第15～17层预取/按需、第18层预取共7个空载回调，load_submit+synchronize约8.5～10μs。
同时其他流计算候选占用并集1917.750μs，约74.6%；因此该空泡不是整卡停工，也不能全计为CPU–NPU通知开销。
空载意味着该次没有计划加载专家，可能与缓存命中等条件有关；未采集逐步专家ID，不能证明每一次都是全命中，也不能据此断言DT绝不会出现。

## 11. 本轮结论

1. 四组有限请求输出一致。MTE组合相对早期配置的端到端与TPOT均降低，长输出整体收益更明显；其中包含C++ LRC、关闭debug和同步方案变化的综合效果。
2. 组合版相对默认版的按需→下一层预取Host间隔在两个长度均缩短；token128预取→按需有加载子集仍回退，不能概括为所有方向稳定改善。
3. 目标加载流几何空泡与严格方向空泡分别回答“流空了多久”和“可关联有加载回调之间空了多久”。token128严格关联覆盖不足且四组不同，不据此做同层配对收益归因。
4. 空载片段内其他设备流仍在计算，回调变短与函数外间隔变长可以同时发生。排除空载只能改善对照口径，不能将剩余间隔全部解释为同步成本。
5. 本轮只有每组一次profile、一次独立服务，20个请求不是20次独立配置复测。数据支持本轮观测趋势，尚不能证明微秒级收益的跨轮稳定性。
