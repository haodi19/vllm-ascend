# Ascend 950PR 单卡 MoE 卸载五组复测：5 token 与 128 token

2026年11月18日晚，Ascend 950PR单卡运行DeepSeek-V4-Flash，物理卡1；Prefill与Decode在同一服务执行。五组含义如下：

| 配置 | 标识 | Host交接 | LRC | debug |
| --- | --- | --- | --- | --- |
| 早期回调 | callback_legacy | 回调 | Python | 开 |
| 关闭debug回调 | callback_python | 回调 | Python | 关 |
| 当前回调 | callback | 回调 | C++ | 关 |
| MTE默认 | mte_default | 共享内存轮询 | C++ | 关 |
| MTE组合 | mte_combined | 共享内存轮询 | C++ | 关 |

MTE默认使用`all/locked/yield`；MTE组合使用`allocated/atomic/yield`，即缩小扫描范围＋原子预检查，保留yield。
全部使用普通加载流；MTE在消费者处严格等待预取完成。早期配置由当前代码复现，不切换历史提交。
前两组只改变debug，第二、三组只改变LRC实现，当前回调与MTE默认比较交接机制，两组MTE比较worker优化组合。

token5、token128顺序执行，每轮按上表顺序启动五个独立服务，每组预热5次、测20次无profiler流式请求，随后单独采集1次profile。
两轮输入均为5个token；token5设置`ignore_eos=false`，实测所有计时请求输出5个token；token128设置`ignore_eos=true`，实测全部输出128个token。
10组计时窗口的MoE MSTX均未激活，前后标记调用数均为0，无进行中的标记回调；profiling和校准探针在独立计时窗口之后执行。

两轮均成功结束，轮内五组请求配置、输出摘要、token用量及工作量摘要一致；清理前未记录EngineDeadError。
token5每份profile包含84次预取、86次按需，实际加载专家次数分别为73、320；token128分别为2436、2494次回调及2242、13942次加载。
这些是本次采集请求的累计次数，不是不同专家ID数量。10份时间线均可用，但均有profiler线程初始化警告。
10份同次采集时钟校准均通过24个留出样本的区间检查；这不等于时间轴没有剩余误差。

每组只有一个服务实例和一次profile，20个请求及数千个回调不能当作同等数量的独立环境复测。
IQR采用各指标独立的3×IQR规则，原始值同时保留；它既可能排除慢样本，也可能排除快样本，不证明这些样本来自外部干扰。

方案2确实受保守余量影响：token128组合的结果为保守36.557μs、直接32.705μs，差3.852μs；原始80.208μs不受此分类余量影响。
表中极窄的方案2边界范围只描述选定对齐坐标下上下界中点的敏感性，不包含几十微秒的完整校准不确定性。
本轮没有出现非法扣除；未知样本仍按上述规则保留，不能把残余数值解释成精确的轮询协议耗时。
