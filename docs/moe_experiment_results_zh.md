## 阅读口径

- **主时延**：新实验以首个非空输出到最后非空输出的 decode 时延为主，保留 HTTP E2E 和 TTFT。历史仅有完整请求时延的批次不改名为 decode。
- **TPOT**：decode /（实际输出 token 数 − 1），使用实际 token 数而非 SSE 块数。Miracle 和扣除计算等待后的方案 2 均为估算，不是重新实测的性能。
- **Host 间隔**：相邻外层 Host 任务结束到下一任务开始。同 Host 时间轴的原始间隔与跨 Host/设备时钟的早晚分类是不同层面的证据。
- **加载流空泡**：MEMCPY、Transpose 等同流任务均计占用；当前口径只保留 `10 ≤ gap < 5000 μs`。历史逐拷贝间隔、未对齐统计、排除零加载关联统计分别保留标签，不混成同一指标。
- **可比性**：分清机器、请求/输出长度、采集批次、加载量、raw/IQR 和计时是否带 profiler/MSTX。一个 profile 内的多层样本不等于多次独立实验；续采不产生新的无采集计时。

## 单卡 MoE 冷热专家卸载优化

DeepSeek-V4-Flash 的专家权重规模较大，单卡推理需要将冷专家保留在 Host DRAM、热专家缓存在 HBM，并在执行过程中按需加载。除了权重传输本身，CPU 策略计算、CPU/NPU 任务交接和搬运提交也会形成等待，影响 Decode 性能。

本工作围绕这些开销，依次完成 **缓存策略 C++ 化、调试开销消除、MTE 共享内存交接与轮询优化，以及消除 Python/GIL 依赖的 C++ 专家更新与搬运提交**。

- **原有优化组合**：相对早期回调，950DT 的 TPOT 降低 **36.76%**；950PR 的 5/128-token Decode 时延分别降低 **40.17%/19.96%**。
- **进一步优化 GIL/C++ 提交**：在已有 MTE 方案上，当前完整提交版本的 5-token Decode 再降低 **8.97%**，完整请求时延降低 **4.77%**。
- **降低搬运附加成本**：提前准备 scale 的目标布局，消除该加载流上的 scale 转置任务，并取消 **8.0625 GiB** 重复 scale 缓冲。

以上收益分别来自各阶段的同机对照，不叠加计算累计提升。本介绍覆盖至 C++ 提交优化，不包含后续独立 DMA 线程的流水方案。

### 一、减少缓存策略与调试开销

原实现由 Python 维护专家访问统计、选择替换槽位，并执行调试统计。优化将 LRC 核心计算迁入 C++，保留缓存算法，同时关闭正式推理中的 debug 工作。

| 优化点 | 指标 | 优化前 → 优化后 | 耗时降低 |
| --- | --- | ---: | ---: |
| LRC C++ 化 | 策略两函数单测耗时 | 33.21 → 4.71 μs | **85.8%** |
| LRC C++ 化 | 实际推理按需策略计算 | 55.70 → 12.33 μs | **77.9%** |
| LRC C++ 化 | 实际推理预取选槽 | 33.11 → 6.10 μs | **81.6%** |
| 单独关闭 debug | PR 5-token Decode | 237.410 → 190.485 ms | **19.77%** |
| 单独关闭 debug | PR 128-token Decode | 7709.594 → 7038.659 ms | **8.70%** |

策略计算和 debug 是两个不同来源的开销，因此通过独立配置组验证。LRC 的局部耗时显著下降；它能否进一步降低完整模型时延，还取决于搬运和设备计算在请求中的占比。

### 二、缩短 CPU/NPU 交接与加载等待

将运行时 Host 回调交接改为 **MTE 共享内存协议**：NPU 发布专家请求，CPU worker 读取请求并完成权重更新，再通知 NPU 继续执行。预取提前发布，与模型计算并行；在真正消费权重的位置保留严格等待。

配套优化包括：

- **普通加载流**：减少逐项拷贝提交成本。预取、按需的 copy_submit 分别由 135.09、585.12 μs 降至 37.04、180.60 μs，降低 **72.58%/69.13%**。提交加同步的降幅较小，因此整体收益继续以模型计时衡量。
- **轮询优化**：仅扫描已分配槽位，以原子读取替代加锁探测，保留 yield，减少 worker 的扫描和锁开销。

### 三、消除专家更新热路径中的 Python/GIL 依赖

一个专家的权重和 scale 需要分项提交搬运。如果提交线程在 Python 执行、对象处理或 GIL 竞争中停顿，设备处理完已提交任务后就会等待。优化将 **专家规划、地址选择、ACL 搬运提交、同步和映射更新**交给 C++ worker，Decode 热路径不再调用 Python、不获取 GIL。

同时完成两项配套改动：

1. **scale 提前形成目标布局。** 加载时直接准备与 NPU 匹配的类型和物理排列，运行时按字节搬运，避免 Tensor 拷贝触发布局转换；复用同一份源缓冲，取消额外的 8.0625 GiB scale 副本。
2. **扩展至 eager/prefill 批量提交。** 预登记地址，由 C++ 整批提交专家字段，减少逐字段的 Python 工作。模型初始化和图注册仍由 Python 完成。

三组配置分别为 **Python MTE**（原 Host 更新路径）、**原生更新 native**（Decode 更新与提交迁入 C++）、**完整提交 native_full**（进一步覆盖 eager/prefill 批量提交）。

### 四、区分计算等待与 Host 交接开销

预取与设备计算并行。**计算可能先于预取结束，也可能晚于预取结束；晚结束的那部分计算会落入预取→按需间隔。** 因此，Host 工作变快后，间隔可能变长，不能单凭这个间隔判断调度是否退化。

为观察交接本身的改善，保留原始数据，并提供两种分析：方案 1 去掉明确“计算晚于预取结束”的样本；方案 2 扣除这些样本中暴露的计算等待。其余样本保留原值。

**PR 原有交接方案的分析结果：** 采用保守判定，单位 μs；方案 2 为基于对齐时间线的估算。

### 用于 HHM 对照的基线结论

当前软件基线为 MTE 组合：每层 24/256 个路由专家缓存、C++ LRC、下一层预取上限 1、
共享内存轮询及消费者处严格等待。新服务器首次实验中，较早期回调，
整体请求均值降低 **4.36%**、所选加载流空泡均值降低 **57.3%**；
另一次流式实验测得平均 TPOT **82.478 ms/token**，较早期回调降低 **36.76%**。

当前输入输出很短，且预分配了较大的 KV cache 和独立 Prefill 池。
后续 HHM 对照应固定硬件、checkpoint、量化布局、上下文长度、并发、MTP 和缓存/预取策略，
以无 profiler TPOT 为主要 Decode 指标，同时报告实际专家访问和传输量。
若改变存储架构并减少显式 H2D，需分别衡量访问时延、有效带宽、计算重叠和容量影响；
本文没有 HHM 实测数据，不据此判断 HHM 已经优于 HBM+DRAM。

## 6. 新 PR 四组 token5/token128 性能对照

**日期**：2026-11-12 夜间；后续 Host/空泡离线重统计日期未完整记录。

**目的**：复测 PR 平台短/长输出收益，检查零加载回调对间隔的影响。

**内容**：四组配置；各 5 次预热、20 次无采集请求、1 次 profile；保留 raw 与排除空载关联数据。

**路径名称**：`/data/w00919836/moeoffload/bench_results/night_four_way_20261112_215723_23693/`；子目录为 `tokens5`、`tokens128`，主文件均为 `summary.txt`。

2026年11月12日晚，新PR服务器单卡运行DeepSeek-V4-Flash，Prefill与Decode同服务执行。两种输出长度各运行以下四组：

- **早期回调**：`callback_legacy`，CPU回调交接，Python LRC，开启debug。
- **当前回调**：`callback`，CPU回调交接，C++ LRC，关闭debug。
- **MTE默认**：`mte_default`，共享内存轮询交接，C++ LRC，关闭debug；`all/locked/yield`。
- **MTE组合**：`mte_combined`，共享内存轮询交接，C++ LRC，关闭debug；`allocated/atomic/yield`，即缩小扫描范围＋原子预检查，保留yield。

#### 计算早晚与两种重统计方案

在预取→按需过程中，设备计算和预取 Host 工作并行。计算可能先完成，也可能晚于预取 Host 结束；后一种情况下，剩余计算等待会计入 Host 间隔，抬高间隔均值。表中“早/晚”均指**计算相对于预取 Host 结束**，计算到达消费位置使用已有设备任务边界区间判断。

- **方案 1**：删除明确晚完成的样本，计算剩余样本均值。
- **方案 2**：对明确晚完成样本，扣除预取结束至计算到达消费位置的经过时间，采用边界区间中点；再与其他样本合并。
- 两方案均为全样本口径：早完成、不确定和无法识别样本保留原间隔；不确定/无法识别没有被归类成早完成。不做 IQR 或额外时长截断。整组无法分类时不提供方案结果。
