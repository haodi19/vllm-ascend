# MoE卸载四组实验数据速查

更新日期：2026-11-13。分别记录DT短输出、新PR短输出和新PR长输出；不同机器的绝对时延不直接比较。

## 四个配置的含义

| 表中名称 | 脚本组名 | 交接方式 | LRC | debug | Worker配置 |
| --- | --- | --- | --- | --- | --- |
| 早期回调 | callback_legacy | launch_host_func | Python | 开启 | 不适用 |
| 当前回调 | callback | launch_host_func | C++ | 关闭 | 不适用 |
| MTE默认 | mte_default | 共享内存轮询 | C++ | 关闭 | all/locked/yield |
| MTE组合 | mte_combined | 共享内存轮询 | C++ | 关闭 | allocated/atomic/yield |

四组均使用普通加载流。两组MTE均在消费者处严格等待，不增加CPU重排。
早期回调是当前代码上的早期配置复现，不是切换历史提交；与其余组同时存在LRC和debug差异。

三批实验均为每组5次预热、20次无profiler计时请求，随后单独采集1次profile。
短输出max_tokens=5；长输出max_tokens=128并开启ignore_eos。
以下raw为原始统计，filtered为3×IQR筛选后的统计；各指标独立筛选，不能累加filtered分项。
大量回调来自单次profile请求，不等于大量独立实验重复。

## 自动报告与128-token漏报修复

后续原四组测试命令不变。每次输出目录自动生成experiment_tables.md，关键表格也附在summary.txt末尾。
表格包含配置、端到端、TTFT、TPOT、Host两方向、加载流双窗口、方向子集状态，以及可用时的miracle假设。
缺失项标为“—”，不写成0；失败实验保留已有数据并标记完整对照未完成。

本次128-token漏报链路：四组/stop_profile请求等待超时，报告标记incomplete；原汇总代码只分析complete，
因而跳过已生成的trace，Host与设备空泡一起缺失。TraceViewParser实际上已结束，JSON也已完整。
具体为何/stop_profile未及时返回，现有日志尚不能定位到profiler内部环节，不归因于某个告警。

主测试脚本现在对incomplete状态也检查已保存trace，验证JSON、文件未变化、设备轨道、回调嵌套和数量覆盖。
通过后标记recovered_intervals，并保留profile_export_status=incomplete，不伪称整个profiler流程成功。
没有文件、截断JSON、回调数量不匹配或MTE算子缺失不会被恢复为有效结果。
临时检查脚本曾拒绝字符串时间戳，是另一个已经修正的错误；主分析器原本支持该格式。

## 四组重复采集方法

`script/run_moe_profile_trials.py`复用原四组实验入口，默认四轮、每配置四份独立profile，共启动16个服务。
每轮将执行顺序循环移位，四种配置各占一次第一、第二、第三、第四位置。
各服务先预热5次，再测20次无采集请求，最后单独采集一次请求；每轮按原流程构建和检查。
重新启动服务避免上一轮profiler停止异常影响下一份采集；停止采集超时默认增加至600秒，
仍保留已有时间线的独立验证，不把超时恢复标记为正常导出完成。

在容器中已加载项目env.sh、进入项目目录后执行：

```bash
python -u -B script/run_moe_profile_trials.py \
  --npu 1 --trials 4 --max-tokens 128 --ignore-eos \
  --warmup-requests 5 --timing-requests 20 --requests 1 \
  --request-timeout 600 --bubble-stream-name 'Stream 56' \
  --output-dir /data/w00919836/moeoffload/bench_results/profile_trials_128_01
```

输出目录必须是新目录。5-token对照使用另一个目录，将`--max-tokens`改成5并删除`--ignore-eos`。
如需一次跑完两种长度，将命令中的`--max-tokens 128 --ignore-eos`替换为`--both-token-lengths`。
两套长度分别执行四轮，共32次服务启动，串行运行；5-token不忽略EOS，128-token启用ignore_eos。
各套结果位于tokens5、tokens128，每套结束后合并到最外层summary.txt及experiment_tables.md，
不跨长度合并均值。中途失败保留已完成部分并停止后续实验。
只需查看最外层summary.txt；experiment_tables.md内容相同，便于浏览。每轮结束刷新一次汇总，
逐轮原始报告和profile保留在trial_01等目录。运行失败停止后续轮次并保存已有结果，不自动重试删除差样本。

汇总分别列出Host两个方向的raw/filtered均值、P50、P95与剔除数，以及加载流full_capture、
callback_window两个范围的均值、累计空泡、样本数和阈值排除数。
设备任务占用包含MEMCPY和Transpose，仅保留10≤gap<5000μs，不对设备空泡再次IQR。
设备方向关联子集单列，标记partial，不能代替完整方向收益。
跨轮以每份profile均值等权汇总，显示逐次值、最小/最大、样本标准差；同轮配对显示逐轮变化及降低次数。
不把几千条回调当成几千次独立实验，也不因某轮较慢而删除该轮。
同时保留端到端、TTFT与TPOT；均值和累计空泡分别比较，避免样本数变化掩盖累计时延。
固定循环顺序不是随机化试验，四轮同向也不自动证明统计显著性或排除服务器状态影响。

Host间隔来自profiler导出的MSTX完整X事件：moe_offload/host_callback标签标识进程、call、kind、layer等。
按同一进程的开始时间排序，只比较紧邻的回调，间隔为后一条开始减前一条结束；
只保留prefetch→reactive、reactive→prefetch两个类型顺序，重叠负间隔排除并计数，零间隔保留。
当前主表没有按层号或解码轮边界筛选，不能一律将reactive→prefetch解释成下一层；
第一条之前、最后一条之后及没有回调标记的Prefill区段不单独计入，但相邻回调间的全部时间会计入。
raw不设置10μs下限或5ms上限；filtered对每份profile、每个方向独立应用
[Q1−3×IQR, Q3+3×IQR]闭区间，样本少于8或IQR=0时不剔除。
原始报告的large_gaps（默认≥100μs）是附加子集，不是Host主表的筛选条件。
Host标记包围Python回调函数体，不直接测量纯GIL等待、轮询或系统调用开销，
回调间隔也不等于NPU空闲；分项耗时与Host间隔不可混用。
