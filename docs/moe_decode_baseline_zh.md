# DeepSeek-V4 单卡 MoE 卸载测试基线与专家加载记录

本文整理单卡运行 DeepSeek-V4-Flash、将 MoE 专家权重保存在 Host DRAM、
在 HBM 中缓存部分专家并按需加载的测试条件和结果，作为后续 HHM 方案对比的基线。
Prefill 与 Decode 在同一服务、同一张卡上执行，没有做 PD 分离。

**硬件标识：本次专家轨迹实际报告为 Ascend950DT_9582。**
本文采用新服务器的实验数据，不将其标记为旧服务器 Ascend950PR 的性能结果。
若 HHM 对照目标是 950PR，需要在相同硬件条件下建立对应的性能基线。

## 1. 四组配置的含义

| 文中名称 | 脚本组名 | CPU—NPU 交接方式 | LRC 策略实现 | 调试打印 | 轮询 worker 配置 |
| --- | --- | --- | --- | --- | --- |
| 早期回调 | `callback_legacy` | `_launch_host_func` 回调 | Python | 开启 `moe_offload_debug` | 不适用 |
| 当前回调 | `callback` | `_launch_host_func` 回调 | C++ | 关闭 | 不适用 |
| MTE 默认 | `mte_default` | 共享内存 generation 标志与轮询 | C++ | 关闭 | `all/locked/yield` |
| MTE 组合 | `mte_combined` | 共享内存 generation 标志与轮询 | C++ | 关闭 | `allocated/atomic/yield` |

早期回调是在当前代码上恢复 Python LRC 和调试打印配置，用于重现早期运行方式，
不是检出历史提交。当前回调迁移了 `observe`、`choose_victims` 等已验证的 LRC 计算，
并关闭调试打印；两项变化共同构成该组与早期回调的差异。

MTE 默认使用设备算子发布请求、Host worker 轮询处理、设备等待完成标志的交接方式。
`all/locked/yield` 表示扫描全部交接槽位、加锁检查、空闲扫描后让出 CPU。
MTE 组合将扫描范围缩小为已分配的交接槽位，并用原子预检查减少空闲时进入锁的次数，
保留 `yield`；这里的交接槽位是同步任务槽，不是 HBM 专家缓存槽。

四组均使用普通权重加载流。两组 MTE 提前发布预取请求，在消费者处严格等待完成；
权重准备和提交仍由 Python/Torch 执行，未启用 CPU 重排、融合规划、ACL 搬运、绑核或 spin。
**后续架构评估采用 MTE 组合作为当前软件基线，保留其他三组用于说明各阶段变化。**

## 2. 测试条件

| 项目 | 配置 |
| --- | --- |
| 模型 | DeepSeek-V4-Flash |
| 拓扑 | 单卡；TP=1、PP=1、DP=1；`enable_multi_card=false` |
| 并发 | 顺序请求，`max_num_seqs=1` |
| 输入与输出 | `The future of AI is`，5 个输入 token；`max_tokens=5`，实测输出 5 个 token |
| 采样 | `temperature=0`，服务 `seed=1024` |
| 上下文上限 | `max_model_len=150000`，实际测试并非 150000-token 长上下文 |
| 批处理上限 | `max_num_batched_tokens=8192` |
| 内存预算 | `gpu_memory_utilization=0.9` |
| 组图 | `FULL_DECODE_ONLY`，`cudagraph_capture_sizes=[1,2,3]` |
| MTP | `method=mtp`、`num_speculative_tokens=2`、`enforce_eager=true` |
| 软件记录 | CANN 9.1.0；Torch `2.10.0+cpu`；torch-npu `2.10.0.post4.dev20260715` |
| checkpoint 量化配置 | `quant_method=fp8`、`fmt=e4m3`、`scale_fmt=ue8m0`、动态 activation、`weight_block_size=[128,128]` |

模型配置用于识别 checkpoint，不单凭配置名称推断每个打包张量的实际位宽；
实际传输量以拷贝描述符字节数为准。

性能实验每组各预热 5 个请求，再测量 20 个无 profiler 请求，最后单独采集 1 个带 profiler 请求，
四组分别启动独立服务。整体时延及分项使用非流式实验结果；TPOT 另用流式实验测量。
专家加载记录在预热 5 次后单独采集 1 个带详细打印的请求，不用于性能比较。
不同实验的时延与加载量不拼接计算带宽或收益。
两次性能实验的输出摘要和 token 用量在各自四组之间一致，不能替代完整模型精度验收。

## 3. 内存与专家缓存配置

### 3.1 HBM 占用

以下为服务启动时的内存占用，四组值基本一致。该口径保留 Prefill 池和 KV 预分配，
不是一个单独剥离 Prefill 的最小 Decode 内存配置。

| 项目 | 日志值 | 含义 |
| --- | --- | --- |
| 总 HBM | 91.75 GiB | 本轮设备可见总容量 |
| 0.9 比例预算 | 82.58 GiB | 服务配置的目标使用预算 |
| 模型权重 | 33.63 GiB | 框架记录的设备侧权重占用，不是整个 checkpoint 或 Host 权重大小 |
| peak activation | 1.62 GiB | 启动内存评估记录的 activation 峰值，不是每个 Decode 步的常驻量 |
| 非 Torch 内存 | 0.12～0.13 GiB | 启动日志测量值 |
| 图相关内存 | 0.43 GiB | NPU graph 内存 |
| 实际 KV cache 预分配 | 47.20 GiB | `Current KV cache memory`；不是日志建议的 46.62 GiB |
| KV cache 容量 | 986866～986910 token | 缓存容量，不是本次请求实际使用长度 |

Host 专家源缓冲区的权重存储为 **129.0000 GiB**、量化参数存储为 **8.0625 GiB**，
合计 **137.0625 GiB**。这是 Host 专家源张量的逻辑存储字节数，不等同于进程 RSS
或已经独立核验的物理 DRAM 常驻量；不能用来推算进程其他内存开销。

### 3.2 专家数量、缓存和预取

| 项目 | 运行配置 |
| --- | --- |
| MoE 层数 | 43 层，层号 0～42 |
| 每层路由专家 | 256 个，ID 0～255；全模型共 11008 个“层、专家”组合 |
| 共享专家 | 每层 1 个，不计入以下 256 个路由专家的缓存统计 |
| 路由 TopK | 每个路由位置选择 6 个专家 |
| Decode HBM 缓存 | 每层 24 个路由专家槽，共 43×24=1032 个槽；每层容量占路由专家数的 9.375% |
| Host 专家源 | 保留全量专家源权重，加载到 HBM 的专家仍可保留其 Host 副本 |
| 热专家预加载 | 开启，排名文件 `expert_rank_gsm8k.json`；运行后缓存成员随 LRC 替换 |
| Prefill 池 | 2 个可复用层池，每个可放 256 个专家；与每层 24 个 Decode 缓存槽分别管理 |
| 预取 | 开启下一层预测；`expert_prefetch_num=1`，本实现每次预取最多加载 1 个缺失专家 |
| 预测输入行数 | `expert_prefetch_tokens=1`；预测命中的专家不需要重新传输 |

这里“HBM 上放 24 个热专家”更准确地说是**每层有 24 个可替换的路由专家缓存槽**，
不是全模型只有 24 个专家，也不是 24 个 ID 在运行期间固定不变。

当前 LRC 配置：近期窗口 32，EMA 系数 0.9；近期频率、EMA、router score、age 权重
分别为 1.0、0.5、0.3、0.01。按需阶段观察实际路由并更新策略；预取根据预测结果提前加载，
实际按需到达后仍需检查缺失并补齐。

## 4. 四组性能结果

### 4.1 整体请求时延

单位 ms，20 个无 profiler 请求。3×IQR 筛选未剔除样本。
此时延包含 Prefill、Decode 和请求处理，不是纯 Decode 时延。

| 配置组 | 均值 | P50 | P95 | 标准差 | 相比早期回调 |
| --- | --- | --- | --- | --- | --- |
| 早期回调 | 4147.959 | 4145.850 | 4165.364 | 11.403 | 基准 |
| 当前回调 | 4012.253 | 4009.417 | 4037.686 | 13.414 | 降低 3.272% |
| MTE 默认 | 3969.174 | 3966.755 | 3983.621 | 10.782 | 降低 4.310% |
| MTE 组合 | 3967.276 | 3963.890 | 4008.605 | 18.749 | 降低 4.356% |

MTE 组合较早期回调减少 180.683 ms，较当前回调减少 44.977 ms（约 1.12%）；
较 MTE 默认仅减少 1.898 ms（0.048%），不足以据此认定组合策略有稳定的额外整体收益。

### 4.2 策略计算与权重加载分项

单位 μs，为带 profiler 请求中逐回调的 3×IQR 筛选后均值。
各指标独立筛选，保留样本不同，不能将表内分项直接相加。

| 按需 gap_debug | 475.943 | 0.496 | 0.536 | 0.507 |
| 预取 load_prepare | 79.491 | 81.999 | 80.525 | 86.482 |
| 预取 copy_submit | 107.163 | 98.510 | 92.735 | 103.423 |
| 预取 load_submit | 241.952 | 210.252 | 207.977 | 188.809 |

MTE 并未使权重搬运的所有分项都下降，例如组合版按需 `copy_submit` 仍高于当前回调。

### 4.3 Host 回调间隔与设备加载流空泡

Host 间隔是前一个 `host_callback` 结束至后一个开始的空白，单位 μs。
每格为“原始均值 → 3×IQR 筛选后均值”；各组每个方向原始样本均为 126 个。

| 方向 | 早期回调 | 当前回调 | MTE 默认 | MTE 组合 |
| --- | --- | --- | --- | --- |
| 预取→按需 | 259.647 → 226.336 | 197.665 → 197.665 | 114.218 → 100.052 | 77.845 → 57.606 |
| 按需→下一层预取 | 219.343 → 210.833 | 216.107 → 216.107 | 110.720 → 98.263 | 89.319 → 80.845 |
| 两方向筛选后样本数 | 119 / 121 | 126 / 126 | 111 / 114 | 104 / 118 |

设备空泡按实际加载流 **Stream 56** 统计，将 MEMCPY、Transpose 等设备任务共同视为占用，
计算相邻占用区间的空白，仅保留 `10 μs ≤ gap < 5000 μs`，不再叠加 IQR。
全采集窗口（含 Prefill）与首个卸载回调开始至末个结束的连续窗口，
在本轮经过该阈值筛选后得到相同的保留样本；这不表示 Prefill 没有空泡。

| 配置组 | 样本数 | 均值 / μs | P50 / μs | P95 / μs |
| --- | --- | --- | --- | --- |
| 早期回调 | 227 | 1531.104 | 1427.000 | 2630.000 |
| 当前回调 | 224 | 779.927 | 731.375 | 1342.800 |
| MTE 默认 | 229 | 754.492 | 704.750 | 1268.800 |
| MTE 组合 | 229 | 654.492 | 589.250 | 1150.400 |

每组两个方向分别有 102、99 个样本；该子集不等于上一表的全部空泡。

| 方向 | 早期回调 / μs | 当前回调 / μs | MTE 默认 / μs | MTE 组合 / μs |
| --- | --- | --- | --- | --- |
| 预取本层→按需本层 | 1624.005 | 793.971 | 807.375 | 698.814 |
| 按需本层→预取下一层 | 1272.947 | 688.288 | 651.720 | 564.210 |

早期回调到 MTE 组合，目标设备空泡均值降低 **57.3%**，当前回调到组合降低 **16.1%**。
该结果包括 LRC、debug、交接机制及 worker 策略的综合变化。
Host 间隔和加载流空白都不等于纯同步成本，其他设备流可能仍在计算，不能解释为整卡空闲。

### 4.4 TPOT

TPOT 表示首个输出之后，平均每个后续输出 token 所需的时间。
本实验按 `(最后一个非空输出文本块到达时间 − 首个非空输出文本块到达时间) / (输出 token 数 − 1)`
计算；输出 5 个 token 时分母为 4。MTP 可成批输出，分母使用服务 usage，不使用 SSE 文本块数量。

下表为每组 20 次无 profiler 流式请求的结果，TPOT 筛选均保留 20/20 个样本，单位 ms/token。
流式实验单独进行，不能与前述整体请求时延相减计算 TTFT 或 Decode 时间。

| 配置组 | 平均 TPOT | P50 | P95 | 标准差 | 相比早期回调 |
| --- | --- | --- | --- | --- | --- |
| 早期回调 | 130.424 | 130.900 | 136.777 | 3.851 | 基准 |
| 当前回调 | 94.473 | 94.249 | 97.493 | 2.094 | 降低 27.56% |
| MTE 默认 | 83.956 | 83.944 | 86.555 | 2.100 | 降低 35.63% |
| MTE 组合 | 82.478 | 80.367 | 93.410 | 4.643 | 降低 36.76% |

MTE 组合平均 TPOT 比当前回调低约 12.70%，比 MTE 默认低约 1.76%；
但组合版的 P95、标准差更高，额外平均收益较小，还不能认为所有请求都稳定加速。
这是短输入、短输出、MTP 开启的客户端观测值，不是长序列稳态 Decode 或单个 kernel 时延。

流式实验还采集了每组 1 次带 profile 的请求，用于估算“Host 回调间隔全部归零”的 miracle 情况：

| 配置或估算 | 带 profile 的 TPOT / ms/token |
| --- | --- |
| 早期回调实测 | 132.963 |
| 当前回调实测 | 101.337 |
| MTE 默认实测 | 90.990 |
| MTE 组合实测 | 87.991 |
| miracle：基于同次 MTE 组合请求估算 | 78.771 |

该 MTE 组合请求首个至最后一个输出之间，可扣除的 Host 间隔并集为 36.8805 ms，
对应每 token 减少 9.220125 ms，得到 78.771 ms/token，较同次带 profile 实测降低约 10.48%。
估算假设 Host/client 时间轴对齐、这些间隔全部位于关键路径且能消除、其他执行不变；
不应用设备空泡的时长阈值或 IQR，不扣除回调函数本体。
**miracle 不是实际第五组，也不是 HHM 性能预测，不能从无 profile 的 82.478 ms/token 中再扣除该值。**

## 5. 实际专家 H2D 加载行为

本次完整性检查通过：1 个请求、298 个事件、无错误、无丢弃，重新汇总与原始总计一致。
其中 43 个 Prefill 池加载事件、126 个预取事件、129 个按需事件；
按需层序列形成 **3 次完整的 43 层遍历**。
下文“轮”指层访问遍历，不是输出 token 序号；一次 MTP 遍历可处理多个路由位置。

### 5.4 专家 ID 示例

第 1 轮第 0 层按需调用，缓存命中的 5 个专家为
`[29,106,107,169,216]`；缺失并完成加载的 13 个专家为
`[6,60,62,74,111,126,132,148,168,203,206,214,235]`。

第 1 轮第 1 层预取事件 45：预测命中 `[170]`，预测缺失 `[5,52,54,111,227]`；
受每次最多加载 1 个专家的上限约束，实际只加载 `[52]`，淘汰 `[13]`。
随后的同层按需事件 46 命中 `[52,170,229]`，其中 `[52]` 来自上述预取；
仍需加载 `[5,36,54,86,94,111,114,154,155,203,210,222,227,235,240]`，共 15 个专家。
这说明预取可以提前满足部分实际路由，但不能用“预取缺失数”代替实际 H2D 加载数。

## 6. 用于 HHM 对照的基线结论

当前软件基线为 MTE 组合：每层 24/256 个路由专家缓存、C++ LRC、下一层预取上限 1、
共享内存轮询及消费者处严格等待。新服务器首次实验中，较早期回调，
整体请求均值降低 **4.36%**、所选加载流空泡均值降低 **57.3%**；
另一次流式实验测得平均 TPOT **82.478 ms/token**，较早期回调降低 **36.76%**。

当前输入输出很短，且预分配了较大的 KV cache 和独立 Prefill 池。
后续 HHM 对照应固定硬件、checkpoint、量化布局、上下文长度、并发、MTP 和缓存/预取策略，
以无 profiler TPOT 为主要 Decode 指标，同时报告实际专家访问和传输量。
若改变存储架构并减少显式 H2D，需分别衡量访问时延、有效带宽、计算重叠和容量影响；
本文没有 HHM 实测数据，不据此判断 HHM 已经优于 HBM+DRAM。
